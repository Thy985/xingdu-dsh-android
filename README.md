## 本机与远程，两种独立模式

- **本机模式**：保留随包 Android Bionic Node.js 24.18.0、官方 DeepSeek Harness `0.2.1-rc.2`、Bash、ripgrep、CA 证书、文件锁与 PTY 助手。前台服务在手机执行 `dsh web`，本机 WebView 仍只导航到 `127.0.0.1:3080`。Android 8.0+ ARM64 可用；无需电脑、Termux 或 Root。
- **远程模式**：首页“连接远程主机”或顶部操作菜单，粘贴电脑上的官方完整启动 URL。局域网或已在系统建立的 Tailscale/VPN 负责连通；应用不会创建 VPN、注册账号、更改 ACL、开启主机公网端口或配置远端 DSH。主机需正确监听可达地址，并按官方要求配置可信主机。`127.0.0.1` 仍指手机本身，不是电脑。
- **数据分开**：远程在 Android 独立 `:remote` 进程及 WebView `remote` 数据目录运行，需 Android 9+；Android 8 仅保留本机模式。切换远程不停止本机引擎，断开不停止远端任务。远程会话关闭后尝试清理其 Cookie、网页存储及缓存；清理不影响本机 WebView。远程刷新/重建可能需要重新粘贴完整认证地址，不持久化启动凭证。

本机工作区在 App 私有 `files/workspaces/default`，本机配置与会话在 `home/.dsh`；远程会话和工作区由电脑管理。原生“手机文件”入口只操作**本机默认工作区**，不是远程上传/下载或跨设备同步。

引擎本机运行不等于模型离线运行：没有附带大模型，仍需在官方设置配置自己的 API。开发验证不读取或使用用户模型密钥。上游版本见 [UPSTREAM.json](UPSTREAM.json)，兼容代码许可保留在 `third_party/runtime/`。官方 upstream 与内嵌 runtime 不因本次功能调整而改写。

## 导出回原文件夹：保留原件的新副本

导入文件夹时，通过系统选择器申请该树的可持久化读写授权；如果提供器实际允许，保存快照与原树的对应关系。“手机文件 → 导出回原文件夹”选择已记录的导入文件夹，并在原授权树内创建新的 `xingdu-export-*` 子目录，复制其当前本机文件及层级。

**不会覆盖或删除原文件，也不是把改动静默覆盖回每个旧文件。** 此次实现的是“回原文件夹保存新副本”，不是双向同步、实时挂载或增量合并。单个散文件导入不建立原文件夹映射；旧版已导入快照没有来源记录，需重新导入文件夹才能使用此入口。授权不支持、被撤销、只读或来源映射失效时会拒绝并提示重新选择/导入，不绕过系统限制。

保留单文件 128 MiB、每批 256 MiB、1000 文件、2000 条目与16层等限制；拒绝越界、符号链接和异常名称。导出时请停止修改工作区文件；不是引擎级一致快照。中断/取消/提供器失败可能留下部分导出子目录，界面会明确提示检查；不借取消操作删除用户原件。持久授权仅用于用户导入的文件夹，不申请全盘访问、Root 或新增 JavaScript 原生桥。

## 远程连接的安全边界

优先 HTTPS，证书错误不放行；HTTP 只有勾选允许并再次确认后，才接受私有 IPv4、Tailscale `100.64.0.0/10`、本地 IPv6 与明确本地域名。域名后缀并不能证明实际路由安全；请仅连接自己信任的主机，VPN/Tailscale 是否已建立由系统负责，本应用不会验证加密隧道状态。

Android 网络安全配置无法按任意私网 CIDR 放行 HTTP，因此本版平台配置允许明文，具体连接由应用层限制：远程主页面和被 WebView 拦截到的 HTTP(S) 资源必须同源，本机 WebView 额外拒绝非本机 HTTP 请求。**应用层拦截不是完整网络沙箱**，尤其不能把 WebSocket、WebView service worker 或同 UID 插件/命令的网络行为说成被全面约束。不绕过 TLS、官方登录、可信主机或操作审批，不启用危险全权限模式。

远程原生文件选择仅为官方页面的用户发起上传服务，不是原生工作区导入；远程下载暂未实现。主机页面需要跨源资源时会受同源门禁限制，应由可信反向代理提供同源资源，不为兼容而关闭限制。

## 0.1.6-dev：系统授权导入与另存为，无需 Root

原生首页增加“手机文件”卡片；进入官方页面后，可从顶部 `⋮ → 手机文件（导入 / 导出）` 使用。无需启动引擎即可传输。没有增加存储/全盘权限，没有改动官方引擎、审批策略或 WebView 的 file/content URL 禁用设置，也没有增加 JavaScript 原生文件桥。

1. **导入手机文件（复制）**：使用 Android `ACTION_OPEN_DOCUMENT` 选择一个或多个文件，逐流读取到 App 私有暂存目录。全部成功后，整体移入默认工作区下新建的 `import-<UUID>/`。同批重名、异常或超限导致整批失败；不会合并或覆盖既有工作区文件，不修改手机原件。
2. **导入手机文件夹（快照）**：使用 `ACTION_OPEN_DOCUMENT_TREE` 选择系统允许授权的目录，通过 `DocumentsContract` 枚举并复制其名称与层级。空目录也保留。只导入本次快照，不实时同步、不自动回写，且**不会把 `content://` 当作 Node/Bash/Git 的普通路径或直接挂载成工作区**。URI 授权不长期保存；再次导入需重新选择。
3. **导出默认工作区文件**：原生文件浏览器只显示 `files/workspaces/default` 内可访问的普通文件/目录，拒绝本地符号链接、特殊文件和越界路径。选择单个文件并确认后，以 `ACTION_CREATE_DOCUMENT` 选择另存为位置。工作区原文件不变。不是目录/ZIP 批量导出；不会自动回写导入来源。

**工作区不是手机共享存储根目录。** 原生传输目标固定为 App 私有默认工作区，通常为 `/data/user/0/io.github.zhanxing.dshandroid/files/workspaces/default`，不猜测官方页面当前选中的工作区。导入完成会显示可复制的实际路径；可在官方工作区选择器打开该目录或其导入子目录。若文件列表未自动更新，重新打开默认工作区。不会自动创建会话、切换官方工作区或执行命令。此版没有新增“手机文件夹直接成为实时工作区”的能力；那需要独立的 SAF 文件系统桥或有明确冲突策略的同步层。

**边界和失败行为：** 每批最多 1000 个文件、2000 个条目（含目录）、16 层，单文件最多 128 MiB、整批最多 256 MiB，按照实际读取字节计数，不信任提供器报告的文件大小。导出单文件也限 128 MiB；导出浏览器每目录最多扫描 200 个条目，超过会明确提示，不默默截断。文件名按 Unicode NFC 规范化并拒绝分隔符、控制/格式字符、不完整代理字符、`.`/`..` 和超过 240 UTF-8 字节的名称；规范化重名同样整批失败。拒绝循环或重复 documentId、虚拟文档和缺失类型的目录条目。SAF 文件提供器决定哪些文档可授权、哪些内容可读写；不绕过系统或其他 App 的私有目录限制。远端/云提供器的逻辑条目不是本地符号链接，按其实际返回的授权流复制。

传输在后台线程执行；一次只允许一个原生选择/传输流程。系统选择取消不会导入；后台复制取消会在检查点中止并清理本批暂存，提供器阻塞时响应可能延迟。Activity 销毁请求取消正在进行的复制；旋转由现有 `configChanges` 保留 Activity。待返回选择器的请求及导出来源通过 Bundle 保存，恢复后重新检查工作区边界。不承诺强杀/断电恢复：进程被杀或清理失败可能留下 App 私有 `files/file-transfers/pending-*`，不会自动把半批导入发布到工作区。失败或取消的**导出**可能留下系统目标位置的不完整文件，界面会明确提示用户检查删除；不擅自删除提供器返回的文档。选择器与文件列表受系统提供器及设备实现影响，尚待真实设备验收。

恢复后如果系统选择器没有返回，可从“手机文件”清除未完成等待；每次选择使用不同请求代次，已放弃选择的迟到结果不会匹配下一次传输。取消是请求而不是回滚：如果取消到达时整批导入已经发布、或导出已经完成，界面会明确提示结果已保存并显示实际结果，不假装撤销已完成的写入。系统另存为应新建文档；目标重名及覆盖确认行为取决于系统文件提供器，导出前请核对所选目标，不把提供器行为描述成应用级绝不覆盖保证。

SAF 原生边界只约束本次传输入口，不是同一 App UID 下恶意插件或命令的隔离沙箱。引擎运行中改动的文件可能导出到不同时间点的内容；需要一致快照时先停止修改。模型仍可能将导入内容发送到已配置的 API，请先用非敏感文件试用。

## 0.1.4-dev：修复优先，让失败可恢复

本轮按“凭证与数据保护 → 服务启停 → 页面恢复 → 手机适配”排序修复，没有更换官方 DSH、扩大 shell 权限或增加原生 JavaScript 桥。

- **P1 · 日志凭证遗漏**：原先 `Authorization: Bearer VALUE` 只隐藏了 `Bearer`，仍留下 VALUE。现对 Authorization、Cookie 整行值采取保守隐藏，并覆盖常见 API key、password、带引号值及独立 Bearer。日志过滤并非任意插件输出的隐私保证，仍不应公开上传原始日志。
- **P1 · 快速启停与进程归属**：停止后立即启动不再被旧的“正在启动/进程仍活着”状态吞掉；旧停止命令只清理自己之前的进程，不杀更新进程，也不覆盖更新启动状态。进程创建后再次检查取消；启动失败、引擎退出和停止时释放 started 服务状态。正常后台运行不随 Activity 关闭而停止。
- **P1 · 首次安装取消与回滚**：散列和单个 ZIP 文件读取期间均可取消；运行时与 marker 一起提交，提交失败恢复旧版本，提交后的备份清理失败不反向删除新运行时。此处只处理可捕获失败，不宣称断电/强杀时的完整崩溃恢复。
- **P2 · 页面重试**：本机就绪探测最多尝试四次，不把临时拒绝连接直接变成永久等待；停止、重试和销毁会让旧回调失效，即使新旧 URL 相同也不会串线。欢迎页主按钮也能恢复已经在运行的引擎页面。
- **P2 · 错误可见**：只有本机主页面完成加载才显示“本机页面已加载”，不再在调用 `loadUrl` 后立即假装连接成功。主文档 HTTP/网络错误和 WebView 渲染进程退出会明确提示重试；状态栏可点击查看完整文字。这里的页面状态不代表模型 API 或 WebSocket 已验收。
- **P2 · 手机适配初始化**：脚本在 body 创建前注入时改为等待 DOMContentLoaded，避免 MutationObserver 空目标错误；关闭适配也清理待处理监听器。没有接管官方发送逻辑或中文组合输入。

新增回归位于 `ConnectionAttemptTest`、`ServiceLifecycleTest`、`RuntimeCommitTest`、`LogParserTest` 与 `tests/mobile-adapter-regression.cjs`。主机页面测试继续使用真实官方界面，未发送模型请求或执行终端命令。完整测试结果见本文末尾的 0.1.4-dev 验证记录。

## 手机组件组合与单列设置流

这版不只是窄屏 CSS：独立插件 `mobile-shell/` 注册到官方公开的 `shell.overlay` 插槽，新增 React 手机导航组件，并只通过 `ctx.layout` / `ctx.sidebarRight` 的公开服务控制官方面板。沿用前端已有的同一个 React，不搬动已有 DOM，不读取 React 私有字段，不复制会话或输入框。

- **会话**：主区占满手机宽度，常驻图标侧栏收进可开关的会话抽屉；点击外侧可收起。
- **输入**：保留同一个官方编辑器；0.1.5-dev 起空会话恢复垂直居中，原有会话继续使用官方粘底输入座位。导航预留高度，长草稿自己滚动。
- **工具**：底部“工具”入口在无会话时显示工作区指引；有会话时打开官方窄屏全屏工具面，顶部有“返回对话 / 文件 / 终端”；文件、预览、终端仍由官方组件和服务持有。返回不清空草稿、不重建编辑器，不主动关闭已有工具标签。
- **退出适配**：原生菜单“关闭手机布局”同时关闭这层组合呈现，回到官方页面，不重载页面；宽屏不挂载手机导航。

插件由 APK 安装到 App 私有 `files/addons/mobile-shell/`，启动时以独立 `--patch` 文件接入。它不写用户 profile，不修改 `runtime.zip`，不增加 Host 服务或执行权限。`prepareMobileShell` 已接入 Gradle `preBuild`，每次构建会重新生成一致的模块资产。

**这不是完整根布局替换，也不是全部配件重组完毕。** 官方根布局同时持有布局 store 与子 slot 的声明/渲染授权；直接 shadow 根会丢失子组件挂载权限，重复声明又会冲突。本版保留官方组件树，以增量导航组件和呈现层完成主流程重组。设置通过公开 `settings.action` 插槽增加分类/详情导航，表单和子 slot 仍归官方所有；已有多分栏/浮动工具状态没有被强制合并或销毁，复杂拖拽布局、所有配件的深度手机重做尚未完成。

## 这一版的手机体验改进

先检查了随包官方前端的真实 360px 页面及布局实现，再在独立 Android 工程内增加适配；没有修改上游仓库，也没有重打包或替换 DSH 引擎。

- 原生顶部改为 48dp 状态栏，启动、停止、重试和日志集中在操作菜单；连接后 WebView 占满剩余空间，欢迎页可滚动。
- 在 600 CSS px 及以下，保留官方导航业务，手机组件把侧栏收进抽屉，让展开的侧栏覆盖主区而不是挤扁主区；设置页改成纵向分类列表，选中后进入单列详情，以“设置分类”返回；弹层限制在可见区域内。未加载独立插件时仍保留基础横向分类适配作为退路。
- 聊天输入与主要按钮扩大触控区域；窄屏减少输入区侧边留白，长草稿保留内部滚动，短视口下限制编辑区高度，不接管官方编辑器的键盘、组合输入或发送逻辑。
- 原生窗口明确使用 `adjustResize`，由系统处理状态栏、导航栏和刘海避让，不在 Web 内重复累加安全区；页面使用可视视口高度限制弹层和编辑区。横竖屏变化保留现有 WebView。
- 跟随系统字体比例，保留双指缩放。菜单的“关闭手机布局”可随时撤销 Web 样式适配，不重载页面或清空草稿。

适配资产位于 `app/src/main/assets/mobile/`，仅由原生端在精确允许的本机 origin 注入，不添加 JavaScript 原生桥。CSS 必须同时满足 Android 注入标记和窄屏条件；宽屏布局不受影响。DOM 标记优先采用官方 data 属性，少数缺少语义标记的节点使用经结构验证的 CSS-module 局部名称，不绑定构建哈希；升级官方前端后必须重跑回归。手机布局开关是恢复官方样式的退路，不是权限开关。

## 安全与已知限制

前台服务立即显示通知，再在后台校验、安装和启动引擎，不在界面主线程解压。运行时安装使用暂存目录与原子目录替换；停止或失败不会删除用户的会话与工作区。重复启动受单实例锁控制，已经安装相同散列时跳过完整解压。

认证地址只经同进程 Binder 传给界面，不广播；日志只在内存保留且会对令牌脱敏。WebView 禁止文件 URL、任意 content URL、混合内容和 JavaScript 原生桥。当前版为支持远程私网地址，平台明文策略及应用层限制见上文“远程连接的安全边界”；本机页面的外部网页仍只能经用户操作交给系统浏览器。

请特别注意这些尚未完成的部分：

1. 保留官方默认 `workspace-write` 与审批策略，不会为了让命令成功而自动开启 `danger-full-access`。Android 上缺少官方桌面 Landlock 等隔离能力；依赖这些能力的受限工具可能报告 `SANDBOX_UNAVAILABLE`。App 私有目录隔离不等于插件之间的安全隔离。
2. Android 硬链接受限，部分文件发布改为 `COPYFILE_EXCL`，保留源文件和“不覆盖已有目标”的约束，但**复制不是原子发布**，写入中崩溃或断电的持久性保证尚未等价实现。因此不要把重要会话或唯一数据副本放入此开发版。
3. 停止流程会终止 Node 主进程；自行脱离的插件子进程/完整进程树回收尚无保证。没有自动无限重启。
4. 相机、语音、系统目录授权、安卓附件选择、桌面文件打开器、所有第三方插件与原生扩展并未逐项完成移植。不承诺官方所有桌面功能可用。
5. 为执行随包 Bionic 程序，本侧载开发版暂用 `targetSdk 28`。这是兼容性折中，不是现代应用商店的发布方案；后续仍需升级进程执行架构与系统兼容策略。

## 本地构建

需要 JDK 17+、Android SDK 35，以及 Gradle wrapper 可访问其依赖源。配置本机 `local.properties` 的 `sdk.dir`，运行：

```sh
./gradlew testDebugUnitTest lintDebug assembleDebug assembleDebugAndroidTest
```

输出为 `app/build/outputs/apk/debug/app-debug.apk`。已附带运行时资产，不需要为了重新编译 Android 应用再次下载整棵依赖。

重新制作运行时需要 Linux、Node/npm、Android NDK 27.2.12479018、dpkg-deb、apt、zip 与 Python；入口 `scripts/runtime/build-runtime.sh <输出zip> aarch64`。依赖来源和许可见 [第三方声明](scripts/runtime/THIRD_PARTY_NOTICES.md)。已附实际解析得到的 npm 隐式锁 `scripts/runtime/dsh-runtime-resolved-lock.json`，但它不等于完整可重放的顶层 npm lock；重新解析的间接依赖与 Termux 软件源可能变化，须重新验收，不能仅靠版本号认定二进制完全可复现。

静态验收：

```sh
python3 scripts/runtime/verify-runtime.py app/src/main/assets/runtime.zip --arch aarch64
```

安卓本机原生验收脚本为 `tests/runtime-smoke.mjs`，检查真实文件锁竞争/释放、Bash、ripgrep、PTY 与 DSH 版本；它需要在目标 Android 环境中运行，不应拿主机 Node 的执行结果冒充安卓验证。
